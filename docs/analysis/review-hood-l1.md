## Проверка сумм (L1, живой газ)
Кэш: `ceilToStep(base × 4)` = `ceilToStep(0.0815 gwei)` = 0.1 gwei < пол 0.2 gwei, значит **0.2 gwei**. Выше пола кэш поднимется, только если base fee > 0.05 gwei (сейчас 0.0204, нужен рост в 2.46 раза).

| Проверка | Формула | L1 (0.0005 / 0.0015) | L1' (0.0005 / **0.0018**, в плане сейчас) |
|---|---|---|---|
| Старт: запас ≥ 5.6M × кэш | 5.6M × 0.2 gwei = 0.00112 | 0.0015 ✓ (отказ при кэше ≥ 0.3 gwei) | 0.0018 ✓ (отказ при кэше ≥ 0.4 gwei) |
| WARN funder | `ceil(0.0005 + reserve + 1 wei, step) + 100k × 0.2 gwei` | 0.0025 + 0.00002 = 0.00252 ≤ 0.0026 ✓ | то же 0.00252 ✓ |
| `fundCreator`, initial buy 0.0001 | `ceil(0.0005 + 0.0001 + reserve, step)` | ceil(0.0021) = **0.0025** | ceil(0.0024) = **0.0025** |
| `pick` у funder | value + 100k × кэш | 0.00252 ≤ 0.0026 ✓ | ✓ |
| Tx creator (Arbitrum upfront) | 0.0006 + gasLimit × кэш | 0.0006 + 5.6M × 0.2 = 0.00172 ≤ 0.0025 ✓; ломается при кэше 0.4 gwei | то же; при 0.3 gwei: 0.00228 ✓ |
| Предел initial buy без второго шага | 0.0005 + b + reserve ≤ 0.0025 | b ≤ 0.0005 | b ≤ 0.0002 (2 шага D10, на lite берём 1) |
| `funderOptionsFromEnv` | low < target, lot ≤ target | 0.00255 < 0.0026, 0.0001 ≤ 0.0026 ✓ | ✓ |

Цифра 5.6M. `quantizeGasLimit(4.56M)` = 5.5M, `quantizeGasLimit(4.61M)` = 5.6M (наблюдаемый максимум 19.10). Оценка выше 4.666M даст 5.7M. Запаса один бакет, и он уже почти выбран чужими запусками с длинным calldata. На прогон не влияет: реальный баланс creator = `ceil(value + reserve)`. В L1 на газ остаётся 0.0019 ETH, это 9.5M gas при 0.2 gwei. Стартовая проверка служит только грубой границей (см. low-находку про 5.6M).

`ceilToStep` (`fees.ts:26`) верен для step > 0. Шаг > 0 гарантирован `weiEnv` (`funders.ts:59`) и `adapter.ts:183`. При `have > 0` перевод = `ceil(need − have, step)`: он кратен шагу, но не обязательно круглый в сумме с остатком. Остаток creator и так публичен, новой информации нет.
