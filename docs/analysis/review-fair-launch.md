## TL;DR

Криптография сделана правильно:
- расшифровка возможна только с `VerifiedBeacon` (проверка подписи раунда закреплена типом);
- `closeAt < t(R)` выполняется;
- UZFL привязан к chainId, launchId и anon-ключу;
- домены дерева 0x00/0x01 разделены;
- `Σ t_i ≤ T` и `charge ≤ amount ≤ hold` доказаны тестами.

Флаг выключен не полностью. **Сервер с выключенным флагом отличим от сервера без фичи** (405/400 на `/api/launches`, F1). В бандле с `BUILD=0` остаётся строка `fairLaunch` из мока (F3).

Главный дефект по существу: **memo-аттестация почти никогда не успевает до раунда drand**. Окно 3–6 с, проверки «слот раньше раунда» нигде нет, а UI утверждает обратное (F2).

Critical-находок нет. Перед включением флага обязательны 2 high и 4 medium.

**F1 · `core/api/src/lib.rs:109-110` · При выключенном флаге маршруты `/api/launches*` всё равно зарегистрированы, поэтому сервер отличим от сервера без фичи.**

**F2 · `core/fair/src/drand.rs:59-61` (R = R(closeAt)+2), `core/ledger/src/verify.rs:479-491` (`matches`), `web/components/fair/commitment-card.tsx:37,68` · Memo с корнем почти всегда попадает в цепь после раунда drand. Это никто не проверяет, а UI обещает обратное.**
Аттестация ценна одним: корень зафиксирован, пока никто, включая оператора, не мог расшифровать заявки, то есть до `t(R)`. Посчитаем:
- `t(R) − closeAt` ∈ (3; 6] с (плюс до 1 с от отбрасывания миллисекунд);
- цепочка задержек до memo: тик core (до 1 с) → idle релейера (1 с, `engine.ts:140-153`; одно задание за раз, L-17) → подпись, отправка, `confirmed` (0,5–2 с).

Memo оказывается на `closeAt + 2…5 с` и позже. При занятом релейере, например если в ту же секунду идёт `fair_create` соседнего запуска, memo гарантированно после раунда. Слот и время блока сравниваются с `roundTime` только в тексте тоста («its slot is before the round»). В `attestation` нет ни `blockTime`, ни флага. `matches` проверяет лишь `out_memo == meta.memo`.

Судья откроет эксплорер, увидит memo позже beacon, и главный тезис «root fixed before anyone could read a bid» станет ложным. Хуже, если это заметят после сдачи.
*Исправление (backend ~1 ч, frontend ~20 мин):*
1. Раунд взять с запасом: `R = round_at(closeAt/1000 + 30) + 1` (≈ 30 с между закрытием и reveal; UX почти не страдает). Инвариант `t(R) − closeAt ≥ 30 с` проверить в тесте `round_math`.
2. Релейер уже возвращает `blockTime` в `Execution` (`executors.ts:270`). Записывать его в `relayer_jobs` (новая колонка `out_block_time`), в `attestation` отдавать `blockTime` и `beforeRound = blockTime·1000 + 2000 < roundTime` (запас на неточность `blockTime`).
3. UI: «anchored before the round» показывать только при `beforeRound`. Иначе нейтрально: «anchored after the round — inclusion still checkable, timing not proven». Утверждение из тоста `commitment-card.tsx:68` убрать.
4. API.md (Commitment), RELAYER.md v3 п. 2: описать поле.

**F5 · `core/api/src/fair.rs:485-551` · Один тик планировщика обрабатывает всё последовательно, и ошибка одного запуска останавливает весь проход.**

**F6 · `core/ledger/src/fair.rs:833-878` · Reveal расшифровывает все заявки внутри одной транзакции Postgres, синхронно, в async-потоке, и число заявок не ограничено.**

*Исправление:*

### 2. Реестр
| Что | Вывод |
|---|---|
| Гонка окна | **ok**: `fl_bid`/`fl_cancel` берут `FOR SHARE` на запуск и сравнивают `close_at > clock_timestamp()`. `fl_close_due` берёт `FOR UPDATE SKIP LOCKED`, поэтому корень строится после коммита всех заявок, успевших до `closeAt`. Заявка после `closeAt` получает 409 даже при отставшем тике |
| Hold номиналом | сетка из конфига (по возрастанию, ≥ `MIN_ACTION_ZAT`). Hold = номинал через общий `submit_in` (frozen, баланс, журнал). Кап создателя — UX-проверка в API плюс обрезка при reveal |
| Отмена | только `sealed` и только до `closeAt`. Ciphertext → NULL, hold освобождается. `fl_cancel_launch` только создателю, остальным 404 (не выдаёт создателя). Гонка cancel_launch ↔ bid разрешается блокировками |
| Reveal в одной tx | корректно, но тяжело → **F6**. Ошибка одного запуска ломает тик → **F5** |
| Распределение | `L_i` → кап создателя → пропорциональная срезка → D10 → `t_i = floor`, `spent = ceil`, `charge = ceil(...)`, clamp по amount. Инварианты `Σ t_i ≤ T`, `spent_i ≤ e_i`, `charge ≤ b_i` проверены рандом-тестом на 500 итерациях. Кап создателя через вогнутость (тест `creator_share_within_cap_by_concavity`). Пыль остаётся пулу |
| После settle | ciphertext удаляется при reveal. Через 48 ч после `finished_at` удаляются `fl_bids`, `creator_pubkey`/`create_action_id` → NULL, суммы в `actions` зачищаются общим janitor. Остаются: `fl_launches` (публичные данные + `total_e`, `lamports_in`, `rate`, это ок), `creator_tokens(mint, anon_pubkey)` навсегда (как у обычного create, известно), `actions.kind` → **F9** |
| `mint_secret` | открытым текстом до settle, обнуляется в той же транзакции, что и settle (обе ветки) → **F10** |

## Что сделать до включения флага (`UNZEEN_FAIR_LAUNCH=1` где-либо, кроме локального стенда)

1. **F2** — запас раунда ~30 с, `blockTime` и `beforeRound` в аттестации, честный текст в UI. Без этого не показывать commitment судьям.
2. **F5** — изолировать ошибки по запуску, параллельный fetch drand, give-up в `TooEarly`.
3. **F6 + F7** — расшифровка вне транзакции в `spawn_blocking`, кап 1 024 заявки, дерево фиксированной глубины 10.
4. **F15** — проверка `replayed` в трёх `fl_*`.
5. **F8, F10** — убрать счётчики из лога, redacted `Debug`.

**Для публичного деплоя до 28.10 (флаг выключен), обязательно:**
6. **F1** — маршруты только при включённом флаге + расширенный тест.
7. **F3 + F4** — мок без `fairLaunch`, дефолт сборки «выключено», `test:bundle:strict` в деплое.
8. **F14** — не запускать fair-launch на публичных сетях до 28.10 (или отдельный ключ аттестаций).

**28.10, при открытии:** README — «оператор видит номинал hold», «никто не может купить раньше или по цене запуска; сразу после — может», «аттестация доказывает время фиксации набора, а не его состав (сумму заявок публично проверить нельзя: ciphertext не публикуется)».
