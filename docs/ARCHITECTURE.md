# Unzeen — архитектура

> Launch anywhere. Stay unzeen.

Zcash shielded-пул — приватный вход и выход. Solana — рынок. Пользователь никогда не светит свой Solana-кошелёк в сделках.

## Компоненты

```
 Пользователь (ZODL / любой Zcash-кошелёк)
        │ shielded ZEC + зашифрованное memo
        ▼
 ┌──────────────────────────┐
 │ core/ (Rust)             │  сканер Ironwood (lightwalletd)  
 │  - scanner               │  парсинг memo → команда
 │  - ledger                │  балансы по anon-ключу (приватный реестр)
 │  - payouts               │  возвраты / продажи → shielded ZEC
 └──────────┬───────────────┘
            │ команды buy / sell / create / withdraw
            ▼
 ┌──────────────────────────┐
 │ relayer + adapters/ (TS) │  vault-кошельки (шардированы) на Solana
 │  - pump.fun              │
 │  - meteora DBC           │
 │  - jupiter (вторичка)    │
 └──────────┬───────────────┘
            ▼
     Solana: pump.fun / Meteora / DEX     ← лента: «unzeen купил …»
            ▲
 NEAR Intents — пакетный ребаланс ZEC → SOL для запаса SOL у пула
```

## Потоки

### Основной режим: баланс аккаунта (депозит заранее)
**Пополнение.** Shielded ZEC на адрес пула, memo: `{v, op:"deposit", anon_pubkey}` → сканер → реестр зачисляет ZEC на баланс anon-ключа. Это единственная обязательная on-chain транзакция пользователя.

**Действия с баланса.** buy / sell / create / claim — подписанные anon-ключом запросы к API (`nonce` + `ts` против replay), исполняются **за секунды**, без транзакции Zcash. Баланс хранится в ZEC, покупка списывает ZEC по текущему курсу из запаса SOL пула; выручка от продаж и creator fees зачисляются обратно на баланс.

**Вывод ZEC.** Подписанный запрос `withdraw_zec` → выплата shielded ZEC на любой UA (по умолчанию с задержкой/батчингом).

Плюс для приватности: время депозита не связано со временем сделок. Минус: запросы идут по HTTP → не логировать IP, поддержать доступ через Tor, ответы не должны раскрывать чужие балансы.

### Режим исполнения (решение владельца 12.10)
Переключатель у кнопки Buy/Sell, по умолчанию — из настройки профиля (по умолчанию **Delayed**):
- **Now** — 1–3 с, без пачки; только для buy/sell/create (не для выводов). **Без Jito** (решение владельца): единый квантованный priority fee на ВСЕ tx пула (Now и Delayed одинаковые на цепочке, без маркера); плоская комиссия Now из `PoolInfo.fees` списывается с баланса. Jito — только для fair-launch. Защищает от наблюдателей в блокчейне, но НЕ от сетевой слежки (провайдер видит время запроса ≈ время сделки) — для неё Tor/VPN или Delayed.
- **Delayed** — пачки раз в 30–60 с, случайный порядок внутри пачки.
- **Max privacy** — третий пункт внутри Delayed: пачки раз в 5–15 мин.
Контракт: поле `exec: "now" | "delayed" | "max"` в SignedAction (buy/sell/withdraw), колонка `exec_mode` в `relayer_jobs`.

### Режим «оплата за действие» — ВЫРЕЗАН (решение 12.10)
Связывал сумму и время депозита со сделкой (особенно при оплате не из Ironwood) → утечка = дисквалификация. Все действия — только с баланса. В memo допустим только `op=deposit`.

**Вывод токенов.** Подписанный запрос `withdraw` → токены уходят на новый Solana-адрес **всегда** с каплей SOL на газ, задержкой (эпохи) и округлением суммы; каждая часть — отдельной tx. **Позиция по mint — на одном vault** (общий инвентарь всех юзеров по этому токену, решение 12.10, D4); правило «вывод с другого vault» снято — оно ломало вывод и «продать всё» и почти не давало приватности. Предупреждение, если сумма вывода совпадает с суммой недавней покупки. «Умный вывод» (разбить на N адресов) — опция поверх. Предупреждение, если сумма вывода совпадает с суммой недавней покупки.

**Запуск.** Подписанный запрос `create` (комиссия с баланса) → свежий vault-адрес создаёт токен на выбранной площадке. Права создателя в реестре — на anon-ключ.

**Сбор комиссий (claim).** Creator fees площадки собираются пулом глобально по расписанию (не по запросу, чтобы не связывать токены одного создателя) → `claim` — только операция в реестре, зачисление на баланс.

**Fair-launch (киллер-фича, решения 12.10: без Jito в v1, commitment root в MVP, число заявок только при ≥5; спека — `docs/analysis/fair-launch.md`).** Окно заявок N минут, суммы зашифрованы drand tlock → после раунда drand: одна атомарная tx `create + buy(сумма всех заявок)` атомарно → токены делятся пропорционально, одна цена для всех, снайперы невозможны.

## Адаптер

```ts
interface LaunchpadAdapter {
  id: "pumpfun" | "meteora-dbc" | "jupiter";
  create(meta: TokenMeta, initialBuyLamports: bigint): Promise<TxResult>;
  buy(mint: string, lamportsIn: bigint, minOut: bigint): Promise<TxResult>;
  sell(mint: string, amount: bigint, minLamports: bigint): Promise<TxResult>;
  quote(mint: string, side: "buy" | "sell", amount: bigint): Promise<Quote>;
  status(mint: string): Promise<"curve" | "graduated">;
}
```

## Модель доверия (честно, для README)
- MVP: оператор пула хранит vault-ключи и реестр → доверие к оператору.
- Roadmap: мультисиг на vault (Squads), FROST t-of-n на стороне Zcash.
- **Viewing key (UFVK/IVK/OVK) не публикуется никогда** — он расшифровывает все memo. Выплаты — `OvkPolicy::Discard`.

## Verify (решение 12.10)
Merkle-sum дерево обязательств реестра (каждый anon-ключ проверяет свой лист и сумму) + публичный список vault на Solana + заявленный резерв ZEC. Проверка: сумма обязательств ≤ активы. Без viewing key.

## Хостинг демо (решение 12.10)
**Зашифрованный том (N2, решение владельца):** `UNZEEN_HOME` (wallet.sqlite, Postgres, ключи vault/creator) — на LUKS/gocryptfs с ручной разблокировкой владельцем; age-ключ сида — вне тома данных (systemd `LoadCredential` / `/etc/unzeen`); снапшоты и бэкапы провайдера выключены. После перезагрузки демо недоступно до разблокировки → мониторинг с алертом владельцу.
Два экземпляра бекенда (core + relayer + Postgres) — `devnet` (Zcash testnet + Solana devnet) и `mainnet`; фронт один, переключатель сети в шапке. Состояние (anon-ключ, баланс) у каждой сети своё.
Всё на своём сервере (VPS): фронт, API, Postgres, релейер. Без Vercel и без Cloudflare-proxy. Access-логи выключены (или без IP и пути), `X-Forwarded-For` не логируется, `NEXT_TELEMETRY_DISABLED=1`, ротация docker-логов. В README: провайдер VPS видит сетевые метаданные. Своей ноды Zebra нет — публичный lightwalletd.

## Защита приватности
- Шардирование vault + ротация (нет «одного гигантского холдера»).
- Задержки и батчинг между депозитом и сделкой; округление сумм.
- Ни один лог не содержит связки депозит ↔ anon-ключ ↔ сделка в открытом виде.
